迁移学习是指：先在数据较多、标注较完整的源领域学习，再把学到的表示、规则或模型迁移到数据较少的新领域，并用少量新数据校准。

在本项目中，源领域可以是 XSAI，目标领域可以是国产卡：

```text
XSAI 白盒数据
→ 学习 profiling 与瓶颈、动作收益之间的关系
→ 用少量国产卡数据校准
→ 在国产卡上诊断和选择优化动作
```

这对项目有价值，但迁移的对象不能简单理解为“把 XSAI 的 counter 模型直接搬到国产卡”。

## 哪些东西可以迁移

### 1. 迁移语义表示

不同芯片的原始字段可能不同：

```text
XSAI: load_wait_cycles
国产卡: memory_pipe_stall
```

但它们可能都映射到：

```text
memory_wait
```

因此最适合迁移的是中间语义层：

```text
raw counter
→ 统一语义特征
→ 瓶颈
→ 动作
```

可以在 XSAI 上学习：

```text
高 memory_wait + 低 data_movement_overlap
→ 数据搬运等待
→ 尝试 double buffering
```

然后在国产卡上只重新学习：

```text
哪些厂商字段能够可靠表示 memory_wait
哪些阈值需要调整
```

这比直接迁移原始 counter 数值更稳妥。

### 2. 迁移动作规则

动作本身通常比 counter 定义更容易跨平台复用。例如：

```text
瓶颈：寄存器压力
动作：缩小 register tile
```

这个动作在不同平台上仍可能成立，但具体实现和收益需要重新验证：

- 国产卡是否有类似寄存器资源；
- Triton 后端是否支持相同调度参数；
- tile 缩小后是否真的改善 occupancy；
- 是否引入额外访存或计算开销。

所以可以迁移：

```text
瓶颈 → 候选动作
```

但需要重新校准：

```text
证据阈值、动作参数、收益大小和风险
```

### 3. 迁移动作收益模型

在 XSAI 上可以训练模型预测：

```text
给定 profiling 状态和动作
→ 动作成功概率
→ 预期 speedup
```

例如：

```text
输入：
memory_wait、DMA overlap、tile size、dtype、shape、动作类型

输出：
double buffering 的成功概率和预期收益
```

迁移到国产卡时，可以用少量国产卡样本微调或重校准模型。

不过 XGBoost 直接跨芯片迁移通常不可靠，因为：

- counter 的取值范围不同；
- 字段单位不同；
- 资源瓶颈不同；
- 同一个动作在不同编译器上的实现不同。

更现实的做法是：

```text
XSAI 模型用于候选动作排序
国产卡少量数据用于阈值和收益校准
```

也可以把 XSAI、国产卡样本合并后训练，并给国产卡样本更高权重。

## 本项目最适合的迁移学习形式

可以设计成四层：

```text
第一层：硬件无关的动作知识
        例如 tile、pipeline、layout、fusion 的作用和风险

第二层：统一语义瓶颈
        例如 memory_wait、register_pressure、sync_stall

第三层：平台相关的 counter adapter
        将厂商字段映射为统一语义字段

第四层：平台相关的阈值和收益模型
        学习何时触发动作，以及动作能带来多少收益
```

迁移时保留前两层，重新校准后两层。

这就形成了一个很清楚的研究问题：

> 哪些优化知识可以跨硬件迁移，哪些证据和阈值必须在目标芯片上重新学习？

## 在项目中的具体用法

### XSAI → 国产卡

这是最有价值的一条迁移路线：

```text
XSAI：
完整 counter + 受控干预 + 详细因果关系

国产卡：
字段有限 + 少量可运行样本 + 厂商 profiler
```

实验可以设置：

| 方法 | 目标 |
|---|---|
| 国产卡从零学习 | 基线 |
| 直接使用 XSAI 模型 | 测试跨芯片直接迁移 |
| 迁移语义层并校准阈值 | 主要方法 |
| 使用 XSAI 规则 + 国产卡少量样本 | 测试低样本效果 |

对比：

- 瓶颈判断准确率；
- 动作选择成功率；
- 正确性通过率；
- 平均 speedup；
- 编译和测量次数；
- 新 shape 上的泛化能力。

### 算子族之间迁移

例如先在 GEMM 上学习：

```text
tile、pipeline、layout、register pressure
```

再迁移到 attention projection 或 convolution。

这类迁移比跨芯片容易一些，因为 profiling 字段可能相同，但算子结构不同。需要把算子结构、shape、dtype 作为上下文输入。

### shape 和 dtype 之间迁移

同一个算子在训练过的 shape 上表现良好，不代表新 shape 仍然有效。可以测试：

```text
已见 shape → 未见 shape
FP16 → BF16
短序列 → 长序列
```

这能判断动作规则究竟学到了硬件机制，还是只记住了具体样本。

## 与 SHAP/XGBoost 的关系

迁移学习可以作用于 SHAP 流程：

```text
XSAI 上学习哪些语义字段最能区分动作
→ 国产卡上只校准这些字段的映射和阈值
```

例如 XSAI 发现 double buffering 主要依赖：

```text
memory_wait
data_movement_overlap
compute_utilization
```

到了国产卡，不必重新搜索几百个字段，而是优先寻找能表示这三个语义量的厂商指标。

但应区分：

- 可以迁移“哪些语义证据值得看”；
- 不能直接假设原始 counter 的数值阈值相同；
- 不能直接把 XSAI 上的 SHAP 排名当作国产卡上的因果结论。

## 这个方向是否值得作为论文创新

值得作为项目的重要实验线，但不建议单独把“迁移学习”作为核心标题。更准确的表述是：

> 面向部分可观测异构硬件的可迁移证据到动作映射。

它的创新点包括：

1. 用 XSAI 白盒干预学习瓶颈和动作之间的机制；
2. 将机制表示为跨平台的语义瓶颈和动作规则；
3. 通过国产卡 profiler adapter 映射目标平台字段；
4. 用少量目标平台数据校准阈值和收益；
5. 测量从白盒到灰盒的性能退化。

建议最终实验至少包含：

```text
国产卡从零学习
XSAI 规则直接迁移
XSAI 语义规则 + 少量国产卡校准
仅使用 raw counter 的模型
仅使用 latency 的 Agent
```

如果“XSAI 规则 + 少量国产卡数据”能够用更少的测量次数达到接近国产卡从零学习的效果，这就是对项目价值最直接的证明。



迁移学习没有唯一算法。它是一类方法，核心是把源平台学到的表示、参数或规则用于目标平台，再用目标平台少量数据校准。

对本项目，推荐采用“语义层迁移 + 小样本校准”，不要一开始就做复杂的深度域适配。

## 1. 本项目需要迁移什么

把模型拆成三层：

```text
国产卡原始 counter
        ↓
平台适配器
        ↓
统一语义特征
        ↓
瓶颈判断模型
        ↓
动作成功率 / speedup 模型
```

例如：

```text
XSAI 原始字段：load_wait_cycles
国产卡原始字段：memory_pipe_stall
统一字段：memory_wait
```

真正应该迁移的是：

- `memory_wait`、`register_pressure` 等语义表示；
- “瓶颈 → 候选动作”的规则；
- 动作收益预测模型的初始参数。

需要在国产卡上重新校准的是：

- 原始字段到语义字段的映射；
- 阈值；
- 动作收益大小；
- 动作的实现参数和风险。

## 2. 推荐使用的算法

### 算法一：监督微调

这是最直接的迁移方式，适合神经网络模型。

先在 XSAI 数据上训练：

```text
fθ(x) → 瓶颈类别或动作收益
```

再用国产卡少量数据更新参数：

```text
θ_target ← FineTune(θ_XSAI, D_target)
```

实现方式是：

- 共享前面的 profiling encoder；
- 冻结大部分共享层；
- 只训练国产卡的输入适配层和输出层；
- 如果目标数据较多，再解冻部分中间层。

但本项目早期不一定需要神经网络。数据量较小时，XGBoost 更合适。

### 算法二：XGBoost 源模型 + 目标平台校准

项目中的推荐基线是：

1. 在 XSAI 上训练 XGBoost；
2. 用源模型产生国产卡上的动作排序；
3. 用少量国产卡样本重新训练或校准。

可以分别训练：

```text
模型 B：profiling → 瓶颈类别
模型 A_i：profiling + 动作 i → 成功概率
模型 S_i：profiling + 动作 i → 预期 speedup
```

国产卡上不建议直接相信 XSAI 的数值阈值。更稳妥的做法是：

- 保留 XSAI 发现的字段和交互关系；
- 用国产卡数据重新拟合阈值；
- 对成功概率做 Platt scaling 或 isotonic calibration；
- 对 speedup 做线性或分段校准。

需要注意，XGBoost 的 `xgb_model` 继续训练只是继续添加树，并不等同于标准意义上的参数微调。目标平台数据很少时，直接继续加树容易过拟合。更稳妥的实现是：

```text
源模型给出初始预测
目标数据训练校准模型
最终预测 = 源模型预测 + 目标平台校准项
```

或者将源、目标数据合并训练，并对目标样本加更高权重。

### 算法三：实例重加权

如果 XSAI 和国产卡的 profiling 分布不同，可以估计目标域样本的重要性。

训练一个域分类器：

```text
输入 profiling 特征
输出：样本来自 XSAI 还是国产卡
```

如果某个 XSAI 样本看起来很像国产卡样本，就给它更大训练权重：

```text
w(x) ≈ p_target(x) / p_source(x)
```

然后使用加权 XGBoost 训练目标模型。

这个方法适合：

- XSAI 数据很多；
- 国产卡标注数据少；
- 两个平台的语义特征仍然具有相同含义。

如果两个平台的硬件机制差异很大，实例重加权无法解决字段语义不一致的问题，必须先做平台适配。

### 算法四：特征分布对齐

如果两个平台已经有相同的语义特征，但数值范围不同，可以使用：

#### CORAL

对齐源域和目标域特征的均值与协方差：

```text
L_CORAL = ||C_source - C_target||²
```

适合解决：

```text
XSAI 的 memory_wait 通常为 0.2～0.4
国产卡的对应特征通常为 0.4～0.8
```

这类尺度和相关性差异。

#### MMD

最小化源域和目标域在核空间中的分布差异：

```text
L_MMD = distance(P_source, P_target)
```

这两种方法更适合神经网络或连续表示。对只有几十个目标样本的项目，先做 quantile normalization、robust z-score 和缺失掩码，通常更简单可靠。

### 算法五：领域对抗训练

如果以后有大量跨芯片数据，可以使用 DANN：

```text
共享 encoder
    ├── 预测瓶颈或动作收益
    └── 判断数据来自哪个芯片
```

通过梯度反转层，让 encoder 学到“能预测瓶颈、但不依赖具体芯片”的表示。

它的代价是：

- 需要较多源域和目标域数据；
- 训练不稳定；
- 难以解释；
- 不适合当前刚开始建立数据集的阶段。

因此不建议把 DANN 作为第一版方案。

## 3. 具体落到 HG-KDA 的实现流程

### 第一步：定义统一样本

每条样本包含：

```text
hardware_id
operator
shape
dtype
compile_config
semantic_features
raw_features
action
correctness
latency_before
latency_after
speedup
bottleneck_label
```

语义特征建议先固定为：

```text
compute_utilization
memory_wait
data_movement_overlap
occupancy
register_pressure
spill_traffic
sync_stall
launch_overhead
```

所有平台都保留缺失掩码：

```text
has_memory_wait = 1
has_bank_conflict = 0
```

这样模型能区分“该字段数值为 0”和“平台没有这个字段”。

### 第二步：在 XSAI 上训练源模型

在 XSAI 上通过受控实验产生样本：

```text
改变 tile
改变 pipeline stage
改变 layout
改变 register tile
改变 fusion
```

训练两个模型：

```text
瓶颈模型：
XSAI profiling → memory_wait / low_occupancy / register_pressure ...

动作模型：
XSAI profiling + candidate_action
→ success probability
→ expected speedup
```

动作模型可以使用 XGBoost，分别为每种动作训练一个模型。

### 第三步：学习国产卡的字段适配器

国产卡原始字段经过适配：

```text
raw_counter_target
→ normalization
→ semantic_feature_target
```

最开始可以用三种方式：

1. 根据厂商文档和专家规则建立映射；
2. 用 XSAI 与国产卡上的对应动作样本学习回归映射；
3. 对每个语义字段重新学习目标平台阈值。

例如：

```text
国产卡 memory_pipe_stall
→ memory_wait = quantile_normalize(memory_pipe_stall)
```

如果某个语义字段在国产卡完全不可观测，就标记为缺失，并让模型使用其他证据。

### 第四步：使用少量目标数据校准

国产卡上针对每个动作采集少量样本，例如：

```text
20 个算子/shape
每个动作 2～3 个变体
```

用这些数据：

- 校准瓶颈分类阈值；
- 重新估计动作成功概率；
- 修正 speedup 预测；
- 学习厂商字段与语义字段的关系。

可以先使用 5、20、50 个目标样本做低样本实验。

### 第五步：推理时选择动作

对一个新的国产卡算子：

```text
1. profiler 采集可见字段；
2. adapter 转成统一语义特征；
3. 瓶颈模型给出候选瓶颈；
4. 每个动作模型预测成功概率和 speedup；
5. 按期望收益排序；
6. Agent 生成 Triton/IR 修改；
7. 编译、验证、实测；
8. 将结果回写数据集。
```

排序指标可以是：

```text
expected_gain_i
= P(success_i) × predicted_speedup_i
  - compile_cost_i
  - correctness_risk_i
```

## 4. 推荐的实际研究方案

建议按三档实现：

### 第一版：无复杂域适配

```text
XSAI 规则和语义字段
→ 国产卡字段人工适配
→ 国产卡阈值校准
```

这版最容易落地，也最适合作为近期实验。

### 第二版：XGBoost + 目标平台校准

```text
XSAI 训练源模型
→ 国产卡少量样本校准
→ 对比国产卡从零训练
```

这可以形成正式实验结果。

### 第三版：跨平台表示学习

当有多个国产芯片和 AMX 数据后，再尝试：

- CORAL；
- MMD；
- 领域对抗训练；
- 多任务学习；
- 留一芯片测试。

## 5. 论文中如何证明迁移有效

至少比较：

```text
1. 国产卡从零训练
2. 直接使用 XSAI 模型
3. XSAI 规则 + 国产卡阈值校准
4. XSAI 模型 + 国产卡少量样本微调
5. 只使用 latency 的 Agent
```

目标平台样本量设置为：

```text
0、5、20、50
```

指标包括：

- 瓶颈判断准确率；
- 动作成功率；
- 正确性通过率；
- 平均和几何平均 speedup；
- 达到相同性能所需的测量次数；
- 新 shape、新算子上的泛化能力。

对本项目最实际的结论是：

> 先迁移“语义瓶颈和动作规则”，再校准“平台字段、阈值和收益模型”。XSAI 用于学习机制和产生高质量先验，国产卡用少量实验完成适配。
