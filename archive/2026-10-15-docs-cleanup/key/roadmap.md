# Roadmap

更新：2026-09-27。用于梳理研究与开发任务，安排近期分工。未明确的负责人暂记为“待定”。

## 总体安排

- **Task 1：XSAI**——开发 XSAI-KernelAgent、XSAI-prof 和 XSAI-analyzer，首先提高 XSAI-BLAS 性能，研究硬件内部信息对优化的帮助。
- **Task 2：国产芯片**——完成 Profiling 工具、kernelgen 相关研究和 Triton-TLE 算子优化，满足基金要求；同时推进智源要求的华为模拟器分析任务。
- **Task 3：NVIDIA**——在 NV + CUDA、NV + Triton 上复现现有工作、探索优化方法、积累经验，后续将经验和人力逐步转向 Task 1、Task 2。

Task 1、Task 2 同时推进，不等待 Task 3 全部完成。

## Task 1：XSAI 上的 Profiling 与算子自动优化

总负责人：待定。

| SubTask | 负责人 | 工作内容 |
| --- | --- | --- |
| **1.1 XSAI-KernelAgent 初步移植与仓库建立** | 待定 | 基于 cuda-optimized-skills，先完成简单 C/C++ 算子的自动修改、编译、正确性验证和性能测量；整理已有计数器、ChiselDB、PerfCCT 的调用方式，建立 GitHub 仓库首版。 |
| **1.2 XSAI-prof 与 XSAI-analyzer 完善** | 待定 | 整理已有性能信息的含义与覆盖范围，增加代码位置关联、性能问题分析和交给 Agent 的输出；参考国产芯片工具能力，根据实际需求逐步补充采集功能，研究关键指标筛选。 |
| **1.3 XSAI-BLAS 优化** | 待定 | 选择待优化的 BLAS 算子，结合 Agent 和 Profiling 工具进行修改，记录正确性、性能变化及对应原因。 |
| **1.4 硬件内部信息对优化的作用研究** | 待定 | 在同一 XSAI 配置上，先提供约定的常规性能信息，再增加内部信息；比较优化效果和成本，确定哪些信息有帮助，并据此提出性能计数器与信息开放建议。 |
| **1.5 Triton/Triton-TLE 扩展** | 待定 | 在 C/C++ 算子优化工作之后，推进 XSAI 上的 Triton/Triton-TLE 支持与 Agent 适配。 |

**推进顺序**：先做 1.1，逐步推进 1.2，共同支撑 1.3；有具体案例后开展 1.4，随后扩展 1.5。

**仓库首版范围**：

- 移植开始时即可建立开发仓库，不等待完整的 XSAI-prof / analyzer，也不要求先完成新增采集功能。
- 先提供 XSAI 的运行流程、已有性能信息入口、简单算子示例和使用说明。
- 预留 NVIDIA 和国产芯片的 backend 目录及说明；待对应仓库准备好再接入 submodule，不创建空 submodule。
- 跨平台调用与分析结果接口随实际接入逐步完善。

## Task 2：国产芯片上的 Profiling 与算子自动优化

总负责人：待定。Profiling 工具相关工作沿用张韩乐、叶驰骏的协作安排，具体子任务负责人按下表记录。

| SubTask | 负责人 | 工作内容 |
| --- | --- | --- |
| **2.1 国产芯片、Profiling 工具及相关研究调研** | 张韩乐 | 从 Ascend 的 msprof / msprof-analyze、摩尔线程相关工具入手，整理设备条件、可采集信息、已有分析能力和缺失信息；调研不少于 5 款国产芯片，为选定两款目标芯片提供依据。 |
| **2.2 国产芯片 Profiler 接入与 Analyzer 开发** | 待定 | 在选定芯片上接入现有工具，整理关键硬件特征与运行指标，补充面向 Agent 的分析功能；完成基金要求的两款芯片上不少于 5 个关键硬件特征的采集。 |
| **2.3 kernelgen 复现与 Profiling 效果评估** | 待定 | 基于智源内部代码复现关键算子的优化结果；比较开启和关闭 profiler 时的表现，分析现有 profiling 实现及其对优化决策的作用。 |
| **2.4 优化记录分析与知识库建立** | 待定 | 分析 kernelgen 的代码 diff、性能信息和修改结果，整理“性能问题 → 优化方法”的适用条件；逐步开展数据驱动建模，验证知识库对后续优化的帮助。 |
| **2.5 Triton-TLE 算子优化** | 待定 | 选择不少于 5 个算子，在两款国产芯片上适配 Agent 并优化；结合 Profiling、分析方法和知识库，完成基金要求的性能验证。 |
| **2.6 华为模拟器 Profiling Analyzer** | 待定 | 明确智源要求的模拟器版本、可获取信息和交付内容，开发相应分析功能；按工具实际能力确定结果验证方式。 |

**推进顺序**：先确认设备、工具和算子；2.2 与 2.3 可同时推进，2.4 从复现记录开始积累，2.5 随可用条件开展；2.6 单独跟踪，不默认作为其他工作的前置条件。

**基金要求单独跟踪**：

- 到 2027 年 3 月完成不少于 5 款国产芯片调研、算子列表和基础采集工具等阶段任务。
- 在两款国产芯片上完成 Profiling 工具及不少于 5 个 Triton-TLE 算子的优化；保存立项时 FlagGems 的对应版本，按确认后的统计方式验证不低于 1.2 倍的加速要求。
- 材料对“平均加速比”的写法存在差异，具体判断方式待确认；不预先将 XSAI 仿真结果计入两款国产芯片的交付。
- 不少于 2 场相关学术活动、不少于 1 项新增发明专利申请及最终报告另行跟踪；协议期限至 2027-09-21。

| SubTask | 负责人 | 工作内容 |
