# HG-KDA 研究定位

更新：2026-10-15。依据本次用户确认整理。

## 核心定位

HG-KDA（Hardware-Grounded Kernel Design Agent）是硬件证据与优化知识驱动的算子优化方法。它将硬件观测关联到具体代码改法及适用条件，通过以下闭环迭代优化：

```text
硬件证据与当前代码
  → 瓶颈假设
  → 优化知识引导的候选生成
  → 完整正确性与性能评测
  → 保留或回退，并更新可追溯的优化记录
```

当前关注如何让 Agent 利用已有证据和已验证的方法，提出有依据的修改，并避免重复历史失败。上述闭环是当前工作描述；其相对现有方法的普遍收益仍需对照实验检验。

## Hardware-grounded 的范围

“硬件依据”既包括硬件结构与执行机制知识，也包括可核对的硬件观测。证据可以来自多个层级：

| 来源 | 可用于研究的问题 | 当前状态/边界 |
| --- | --- | --- |
| 真机 profiling | 流水活跃、数据搬运、计算、控制与启动开销的线索 | 910B 当前使用的动态证据；XSAI 使用 HPM/ChiselDB profiling 做诊断 |
| 白盒 RTL 仿真与分析 | 将指令、微架构行为与性能联系起来 | XSAI 的研究平台基础；具体已接入字段、分析接口与覆盖范围以服务器仓库为准 |
| 周期精确模拟器 | 深入检查执行时序及资源约束 | 作为分析层级的探索方向；按用户本次确认，尚未接入所讨论的深化分析流程 |
| 指令流分析 | 检查编译实现、依赖与数据复用等细节 | 作为深化分析方向，尚未接入；不能仅因目录中有相关工具指南就认定已经使用 |
| 硬件与优化知识 | 解释证据、限定动作条件、提供有效方法和失败约束 | XSAI 硬件知识库及昇腾优化知识正在工作流中完善 |

RTL 仿真、周期精确模拟与 profiling 并非互斥分类：RTL 仿真本身也可提供周期级行为，profiling 也可采集仿真中的计数器。状态记录应写具体工具、数据和分析方式，不能只用这些名称推断接入程度。

Hardware-grounded 的关键是决策有可追溯的硬件依据，并经实际实验裁决。更深的观测不自动带来更好的优化；是否值得接入，应由具体问题与实验成本决定。

## 三条平台工作线

- **XSAI**：建立 xsai-kda skill，接入 xsai-blas profiling tool，完善 workflow 与硬件知识库，通过 HPM/ChiselDB 诊断瓶颈并优化 XSAI-BLAS。
- **国产芯片**：当前围绕昇腾 910B 和 FlagGems，使用 profiling 与优化知识形成无人值守闭环；后续针对复杂算子判断是否需要更深层分析。
- **NVIDIA**：研究 CUDA 优化流程的分段化与方法融合，并准备 KernelBand 的 Triton 复现，为各线积累可检验的方法经验。

三条线均保留，各自维护代码仓库。国产线具有独立的真实平台研究与交付目标，不要求先完成 XSAI 再开展工作。

## 待探索方向

以下方向经用户确认暂列探索，不作为既定实现要求：跨芯片统一证据层、白盒到灰盒迁移、问题条件化 Top-K，以及 XGBoost/SHAP 等特征分析。

周期精确模拟和指令流分析也应从复杂算子的实际疑问出发评估。当前不预先承诺统一 schema、统一 runner、固定知识库规模或通用动作阈值。

## 结果与结论边界

性能结果保留具体任务、版本、输入与测量口径。profiling 规则提出的是瓶颈假设，最终采纳由正确性和性能评测决定。某次优化成功不能单独证明诊断因果性、知识库普遍有效或跨芯片可迁移。当前数值与已知限制见[当前进展](当前进展.md)。
