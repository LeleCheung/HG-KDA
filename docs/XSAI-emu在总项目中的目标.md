# XSAI-emu 在总项目中的目标

总项目对 XSAI-emu 的目标，不是把它当成一个单纯的模拟器或最终性能测试工具，而是把它作为：

> 高可观测、可干预的白盒研究平台，用来研究“哪些 profiling 证据真正解释算子性能，以及这些证据如何指导优化动作”。

## 具体目标

### 1. 构造可控的算子变体

在相同算子语义下改变 tile、layout、循环顺序、pipeline、线程组织、数据类型等，产生一组可比较的实现。

### 2. 获得尽可能完整的证据

利用 XSAI-emu 的 guest 周期、指令数、RTL counters、指令/uop 流、流水级时间戳、ChiselDB、load replay、DRAMSim3 和编译产物，观察不同实现为什么快或慢。

### 3. 验证 profiling 证据与瓶颈之间的因果关系

例如验证某个 stall、访存行为或资源压力是否真的对应某类性能瓶颈。不能只依赖 counter 相关性，而要通过修改 tile、layout、pipeline 等方式主动干预。

### 4. 校准“证据 → 瓶颈 → 优化动作”映射

最终希望得到类似以下的闭环：

```text
profiling 证据
    ↓
语义瓶颈判断
    ↓
候选优化动作
    ↓
编译、正确性和性能验证
```

这为后续 Agent 提供可追溯的训练数据、规则和验证闭环。

## XSAI-emu 与国产芯片的分工

```text
XSAI-emu：解释机制、构造数据、验证因果
国产芯片：验证真实工具条件下能否迁移
```

## XSAI-emu 的边界

XSAI-emu 不是：

- 真实 XSAI 芯片性能的完全替代品；
- CUDA 或国产芯片 profiler 的直接替代品；
- 自动生成高性能 kernel 的完整系统；
- 证明某条优化规则跨平台有效的充分依据。

## 一句话总结

项目总目标是“从 Profiling 证据到算子优化动作：XSAI 白盒研究与国产卡灰盒验证”。其中 XSAI-emu 主要承担“白盒机制研究和证据校准”这一部分。
